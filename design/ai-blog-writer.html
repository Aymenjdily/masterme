How I Built Daily Infra Cost Tracking for 6 Neon Projects
/blog/how-i-built-daily-infra-cost-tracking-for-6-neon-projects
ExcerptA nightly job, one row per project per day, and a Recalculate button: how I stopped guessing what my side projects cost.

The problem: costs I only saw at the end of the month

I run 6 projects on Neon and one shared Vercel plan. My dashboard called Neon's API on every page load, which was slow, and the totals quietly double-counted projects that also had a linked monthly cost.

EditRewrite

One row per project, per day

The fix was to store the estimate instead of fetching it live. A nightly cron at 05:00 writes one snapshot per project; running it again the same day replaces that day's row.

typescriptawait prisma.infraCostSnapshot.upsert({
  where: { projectId_day: { projectId, day } },
  create: { projectId, day, neonUsd },
  update: { neonUsd },
});

What I'd do differently

  • Store the Neon project id with each reading, so relinking starts a clean series
  • Show "stale" instead of hiding a failed reading
